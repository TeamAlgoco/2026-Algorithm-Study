1. 적용 알고리즘 개념
    - 정렬 & 커스텀 비교 함수
    - 숫자 크기순이나 사전순으로 정렬하는 게 아니라, 두 수를 이어붙였을 때 어느 쪽이 더 큰가라는 기준에 따라 정렬해야 하는 문제

2. 접근 방식(or 개념)
    - 두 수만 보고 순서를 정할 수 있음
    - 3, 30 → 330과 303 중 330이 더 크므로 3이 앞에 와야 함
    - 6, 10 → 610과 106 중 610이 크므로 6이 앞에 와야 함
    - 이 규칙으로 전체를 정렬하면 가장 큰 수가 됨
    - numbers의 각 원소의 자릿수가 서로 다를 수 있기 때문에 숫자 크기순으로 정렬하면 안 되고, 붙인 결과를 비교해야 함
    - 빅이슈: 원소가 전부 0일 경우, 결과는 “00..”이 됨. return은 “0”이어야 하기 때문에 이를 고려해야 했음

3. 기본 코드에 대한 설명
    
    ```python
    def solution(numbers):
            """ 두 값을 받아 순서를 정하는 함수를 sort가 쓸 수 있는 형태로 바꿔주는 함수"""
        from functools import cmp_to_key
        
        """숫자를 이어 붙이기 위해 문자열로 변환"""
        numbers=list(map(str, numbers))
        
        """cmp_to_key(): 두 값을 직접 비교하는 함수를 sort()가 사용할 수 있는 형태로 바꿔줌"""
        numbers.sort(key=cmp_to_key(lambda x,y: int(y+x)-int(x+y)))
        
        """0 처리"""
        return "0" if numbers[0] == "0" else "".join(numbers)
    ```
    
    - `cmp_to_key()` :
        - 값을 다음과 같이 해석함
            - 반환값 < 0 이면 x가 앞에
            - 반환값 == 0 이면 순서 유지
            - 반환값 > 0 이면 y가 앞
        - int(y+x)-int(x+y) 는 y+x가 더 클 때 양수가 되고, 그럼 y가 앞으로 감
        - 즉 두 숫자를 붙였을 때 더 큰 값이 나오는 순서대로 숫자를 배치해줌

    - `"0" if numbers[0] == "0"`
        - numbers 정렬이 끝났을 때
        - 맨앞, 즉 제일 큰 숫자가 0이면 모든 원소가 0이라는 뜻임
        - 이때만 “0”을 반환함
        - `str(int("".join(numbers)))` 을 하면 앞의 0을 다 날릴 수 있긴 한데,
        - len(numbers)의 최대값이 100,000이라서 시간 오래걸릴 것 같아서 안 씀

4. 코드 개선사항
    - (클로드와 깊은 대화…)
    - `cmp_to_key`는 느림
    - 원소마다 객체를 하나씩 더 만들고, 값을 비교할 때마다 Python 함수를 호출하고 int() 변환도 하기 때문
    - 원소가 1,000 이하라서 자릿수가 최대 4자리이므로, 이 점을 이용하면 더 빠르게 만들 수 있음
        
        (참고: https://esoongan.tistory.com/103)
        
        ```python
        def solution(numbers):
            numbers = list(map(str, numbers))
            numbers.sort(key=lambda x: x * 3, reverse=True) # 이 부분!!
            return "0" if numbers[0] == "0" else "".join(numbers)
        ```
        
        - `x * 3`은 문자열을 3번 반복한다는 뜻
        - `"3"`은 `"333"`이 되고 `"30"`은 `"303030"`이 됨
        - 이렇게 늘려놓고 사전순으로 정렬하면 `x+y`와 `y+x`를 비교한 것과 같은 결과가 나옴
        - 길이가 짧은 쪽이 반복되면서 자기 자신의 앞자리로 채워지기 때문
        - 원소 10만개 기준, `cmp_to_key` 보다 속도가 10배 빨라짐
        - 다만… 이는 원소가 1,000 이하라는 조건 하에 가능한 거고,, 값이 더 커지면 반복 횟수가 늘어나기 때문에 이 부분은 어떻게 고민해야 하는지 모르겠음!

5. 시간 복잡도 및 공간 복잡도
    - (클로드와 깊은 대화…)
    - 원소 개수 → n (0 ≤ n ≤ 100,000)
    - 한 원소의 자릿수 → d (1 ≤ d ≤ 4)
    - 시간복잡도: $O(n \log n)$
        
        ```python
        def solution(numbers):
            from functools import cmp_to_key # O(1)
            numbers=list(map(str, numbers)) # O(n*d) : 원소 하나당 str() 한 번 호출, 총 n번. 그리고 str() 하나가 자릿수만큼 걸리므로 *d
            numbers.sort(key=cmp_to_key(lambda x,y: int(y+x)-int(x+y)))
            return "0" if numbers[0] == "0" else "".join(numbers)
        ```
        
        - line 2 → O(1)
        - line 3 → O(n*d) : 원소 하나당 str() 한 번 호출, 총 n번. 그리고 str() 하나가 자릿수만큼 걸리므로 *d
        - line 4
            - 두 가지를 곱해야 함
                1. 비교횟수 →  $O(n \log n)$
                    - 원소를 2개씩 꺼내 비교함
                    - sort()는 이진 삽입 정렬 방식을 사용함 → $O(n \log n)$ 양상
                2. 비교 한 번당 시간 → $O(d)$
                    - 비교할 때마다 lambda 함수 실행됨
                        1. y+x → 문자열을 $d_y + d_x$ 개 복사
                        2. int(y+x) → 문자열을 하나씩 읽으면서 int로 바꾸고, 총 $d_y + d_x$ 번 읽음
                        
                        3-4. x+y에 대해서도 위 과정을 수행함
                        
                        1. int(y+x)-int(x+y): 뺄셈 한 번
                    - 따라서 문자열의 길이에 비례해서 작업이 증가함 → $4 * 2d$ → $O(d)$
            - 전체 =  $O(n \log n)$ * $O(d)$ ⇒ 어차피 $d$는 최대 4.. ⇒ $O(n \log n)$

    - 공간복잡도: $O(n)$
        1. line 3
            - 원소 n개짜리 문자열 리스트 생성 →  $O(n)$
        2. line 4
            - `cmp_to_key` → 원소마다 객체 생성 & 각 문자열이 d만큼 자리 차지 → $O(n)$
            - sort 정렬 과정 → $O(n)$
        3. line 5
            - 문자열 길이 n*d → $O(n)$

6. 사용 라이브러리 정리
    - functools.cmp_to_key : 두 값을 비교하는 함수를 `sort`에서 쓸 수 있게 변환
    - map, str : 숫자를 문자열로 변환
    - list.sort : 정렬
    - str.join : 문자열 이어 붙이기

7. 기타(문제 풀이에 어려웠던 점, 구현하고자 했는데 실패한 방식)
    - 문제 풀이에 어려웠던 점
        - 원소가 0만 들어왔을 때의 처리
    - 구현하고자 했는데 실패한 방식
        - 처음에는 (str 변환 + 사전순 정렬)한 후, 붙어있는 두 개씩 확인하면서 순서를 바꾸려고 했는데
        - 한 번 자리 바꾸고 나서, 그 값이 또 자리를 바꿔야 할 수도 있을텐데
        - 그 자리는 다시 확인할 수 없는 문제가 있었음
